## A. Официальная идентичность

| Поле | Значение |
|---|---|
| Название | **HERMES** |
| Расшифровка | Modular Multi-Tenant Business Orchestration Platform |
| Слоган | One orchestrator. Multiple capabilities. Infinite business configurations. |
| Владелец | Latysh Development |
| Дата «второго рождения» | 27 ноября 2026 |
| Историческое имя | SupportOps Agent (Epoch I) |
| Первый предметный домен | SupportOps (поддержка клиентов: заказы, возвраты, support cases) |

### Миссия (предварительная)

Дать малому и среднему бизнесу набор подключаемых бизнес-возможностей, исполняемых под контролем детерминированных границ безопасности, где интеллект применяется только там, где он нужен.

### Предварительное продуктовое видение [Г]

1. Организация (tenant) получает **свой набор** возможностей: реестр объектов, политики, интеграции, специализированные агенты, шаги с участием человека.
2. HERMES **исполняет** сконфигурированный бизнес-процесс и возвращает бизнес-результат; способ получения обращения и доставки результата — взаимозаменяемые каналы.
3. Полномочия модуля определяет доверенный код и конфигурация tenant, **никогда** — вывод LLM.
4. Эффективность измеряется результатом (стоимость, время, токены на успешный исход), а не числом вызовов.

### Принципы, унаследованные из Epoch I [Ф — зафиксированы в коде и тестах]

- Deny-by-default Authorization Gate, независимый от LLM (`authorization.py`, `tool_executor.py`).
- Доверенная идентичность подставляется приложением, а не аргументами модели (`requires_trusted_identity`).
- Fail-closed: сбой классификации/политики/ответа ведёт к детерминированному безопасному исходу.
- Metadata-only trace (SR-4): сырые данные и текст исключений не покидают границу.
- Неразличимость «чужой» и «несуществующий» объект (404/`None`).

### Принципы эпохи II (из директивы)

- Интеллект там, где нужен; детерминированное остаётся детерминированным.
- Не проектировать избыточную инфраструктуру без доказанной необходимости.
- Каждый проект экосистемы самостоятелен (никакого единого runtime).
- Learn from outcomes, not activity.

| 2026-11-27 | Решение владельца: Epoch I завершена, начинается Epoch II — HERMES |

### Почему переход оправдан (и чем ограничен)

- **Что говорит в пользу [Ф]:** SupportOps уже содержит нетривиальный фундамент безопасного исполнения (gate, trusted binding, sanitization, run isolation), мультитенантный сервисный слой (credential → tenant → tenant-scoped репозиторий) и lease/fencing-схему для запусков. Эти механизмы не привязаны к возвратам.
- **Чем ограничено [Ф]:** в агентном ядре `supportops_agent` нет ни одной ссылки на tenant (`grep -ri tenant src/supportops_agent` → 0); реестр инструментов и данные — модульные глобальные объекты; конвейер прогона жёстко содержит классификацию тикета и оценку возврата. «Оркестратор» (несколько модулей, делегирование, пауза/возобновление) в коде отсутствует.
- **Вывод [В]:** HERMES сегодня — *укреплённый однодоменный агентный рантайм + мультитенантная сервисная оболочка*. Утверждение «мультитенантный оркестратор» — цель, подлежащая проверке экспериментом (см. `04-alternatives-and-commercial-validation.md`).

### Как читать историю

Документы Epoch I не переписываются. Их термины («SupportOps», `SUPPORTOPS-*` идентификаторы Stories, `SupportAgent`) остаются корректными для своей эпохи. В документах Epoch II они используются как собственные имена существующих артефактов.
