## 2. Что менять не нужно (рекомендация)

- **Таблицы БД, `tickets`/`runs`:** нейтральны; не трогать.
- **Идентификаторы Stories и ветки Epoch I:** это история; не переписывать. Новые Stories эпохи II получают префикс по решению владельца (например `HERMES-*`).
- **`supportops_agent`:** содержит именно *предметный домен SupportOps*; логичнее **сохранить** имя как имя домена и переименовать по смыслу, когда ядро будет отделено (см. §3, фаза 3) — то есть имя ядра станет `hermes_*`, а `supportops_agent` останется доменом. Массовое переименование «всё в hermes» **было бы неверно по смыслу** (оно затёрло бы различие ядро/домен).

## 4. Предусловия и проверки на каждом шаге

1. Все активные Stories, затрагивающие переименовываемые файлы, завершены или явно согласованы (в частности API-004 HTTP-slice, EVAL-001, правящие `config.py`/тесты).
2. `uv lock --check` без изменений (если не менялось имя дистрибутива); полный `pytest` (offline) и PG-набор (`SUPPORTOPS_REQUIRE_PG=1`) зелёные: сейчас 934 passed offline, 1072 с PG по отчёту INTEGRATION-GATE-01.
3. Статические тесты границ (`test_security_static_boundaries`, `test_app_skeleton`) обновляются **в том же коммите**, что и пути.
4. Secrets-окружение: список переменных окружения во всех средах инвентаризован владельцем (в репозитории окружений нет — **[Н]**).
5. Отдельный коммит на каждый шаг; без смешивания с функциональными изменениями.
