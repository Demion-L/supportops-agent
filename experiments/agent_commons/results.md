# Результаты AC-EXP-001

Воспроизведение: `python3 run_experiment.py` (30 seeds × 100 задач, ~2 с, без сети). Два прогона дают побайтно
одинаковый вывод. Тесты: `python3 -m pytest tests -q` → 72 passed.

## Гипотеза
Проверенный межагентный опыт улучшает качество решения задач по сравнению с локальным решением без Commons.

## Методология
* Синтетический детерминированный мир (`simulator.py`): 4 типа проблем, контекст из закрытого словаря, скрытые от
  агентов правила решения. Исход определяет только мир; оценивает его независимый Evaluator.
* Один и тот же поток задач (по seed) подаётся всем режимам. 30 seeds варьируют лишь порядок/состав потока.
* Метрики исхода считаются по состоянию мира, не по самоотчётам.
* Корпус B (12 рекомендаций) содержит верные, контекстно-ограниченные, неверные с высоким `confidence`
  (0.90–0.95) и 2 намеренно вредные рекомендации.

## Режимы
| Режим | Смысл |
|---|---|
| baseline | A без Commons: playbook «одно действие на тип проблемы» (контекст игнорируется) |
| local_expert_playbook | **потолок**: локальный контекстный playbook (экспертное знание, без Commons) |
| commons | Commons + Evaluator + контекстная оценка |
| commons_no_evaluator | Commons без Evaluator (ранжирует только confidence) |
| commons_global_score | оценка без контекста (ablation S9) |
| commons_outage | Commons недоступен |
| commons_faulty_filter | сервер не фильтрует применимость |
| commons_policy_gap | локальная политика пуста |
| commons_2agents_shared / _private | 2 агента: общий Commons vs приватные (измерение передачи опыта) |
| naive_trust | демонстрация угроз: слепое доверие, без валидации/политики/оценки |

## Парные сравнения (одинаковые потоки)
* commons − baseline: **+0.346** success (улучшение на 30/30 seeds).
* commons − **local_expert_playbook**: **−0.043** (хуже на 30/30 seeds).
* commons_no_evaluator − baseline: −0.213 (хуже на 30/30).
* shared − private (передача опыта между двумя агентами): **+0.045** success (30/30 seeds).
* policy_gap: вред в 2 % задач (по одному разу на вредную рекомендацию × контекст), затем подавляется обучением.

## Динамика (success по четвертям потока)
commons: 0.839 → 0.991 → 1.000 → 1.000; commons_2agents_private: 0.728 → 0.949 → 0.976 → 0.997;
commons_2agents_shared: 0.839 → 0.991 → 1.000 → 1.000; baseline ≈ 0.61 без динамики.

## Петля обратной связи (§12)
Подтверждено тестами и ledger: отрицательный исход рекомендации в контексте снижает её оценку ниже порога (0.22 после
одной неудачи) и она перестаёт предлагаться в этом контексте; положительный — повышает (≈0.78 после одного успеха).
Провал в `processing` не отключает ту же рекомендацию в `shipped` (S9); глобальная оценка этого не умеет (0.864 против
0.957). Цена исследования: одна неудача на пару (рекомендация × контекст), ≈4 из 100 задач.

## Стоимость коммуникации
commons: ≈293 обращений и ≈980 детерминированных единиц на 100 задач (≈124 KB), т.е. ~3 обращения на задачу.
Стоимость публикации корпуса (12 `share`) и работы Evaluator в обращения агентов не входят (Evaluator учтён
в cost_units, `share` — нет). Режим outage показывает 100 неудачных попыток `ask`, при этом исходы ≡ baseline.

## Независимое ревью и что по нему сделано
Ревью (`security-engineer`, без предзаданного вердикта) нашло недостатки; исправлено и покрыто тестами
(`tests/test_review_regressions.py`): подмена вложенного `applicability` через возвращённый объект (теперь
read-only); раздувание/саботаж статистики повторными заявками на одно исполнение (дедупликация по
`case_ref`×действие); падение A на любых ошибках Commons кроме `Unavailable` и отсутствие проверки `problem_type`;
отравление лога некорректным событием; неоткатываемая неудачная запись; деление на ноль при n<4; метрика
`harmful_rejection_rate` считалась по показанным, а не рассмотренным кандидатам. Добавлены режимы
local_expert_playbook, commons_policy_gap, 2agents shared/private.
Принятые как **ограничения** (не исправлены): см. ниже п. 6–9.

## Выводы
**Подтверждено** (в рамках синтетического мира):
1. Commons+Evaluator существенно лучше «слепого» baseline (+0.346 success; 30/30 seeds).
2. Независимый Evaluator решающе важен: без него Commons хуже baseline, потому что `confidence` вводит в заблуждение.
3. Контекстная оценка лучше глобальной (0.957 vs 0.864).
4. Отказ Commons не ухудшает исходы относительно baseline (S6); отказы локальной политики, локальная проверка
   применимости и атаки на самоотчёты (T1–T14, см. threat-model.md) воспроизведены и отражены.
5. Передача опыта между агентами даёт небольшой выигрыш на старте: +0.045 success (общий vs приватный Commons).
6. Рекомендации одного агента можно использовать другим без доверия на слово: при пустой политике вред не исчезает
   сразу (2 %), но обучение подавляет повторения.

**Не подтверждено / опровергнуто:**
7. Что Commons лучше **хорошего локального решения**: экспертный локальный playbook даёт 1.000 > 0.957. Выигрыш над
   baseline означает «доступ к знанию лучше слепого playbook», а не преимущество обмена как такового. Корпус B
   построен по тем же правилам, что и мир; baseline намеренно имеет пробелы. Размер эффекта — свойство дизайна,
   а не оценка реального выигрыша.
8. Что эффект переносится на реальный мир: мир детерминирован, без шума и задержки обратной связи; одной пробы
   достаточно для «выучивания», что завышает скорость обучения.
9. Что защита выдерживает активного противника: часть векторов остаётся открытой (ниже).

## Ограничения (в т.ч. принятые по ревью)
* Нет аутентификации агентов/авторов: `agent_id`, `author_id` — строки; возможен спуфинг, предсказуемые
  `application_id` позволяют DoS (занять id), любой участник может опубликовать новую версию чужой рекомендации и
  тем «обнулить» историю вреда (репутация привязана к версии).
* Оценка зависит от отчётности: исполнение без `Feedback` Evaluator не видит (survivorship bias; именно так
  работает naive_trust). Evaluator не сканирует мир на «молчаливые» исполнения.
* Идентификаторы (`case_ref`, `agent_id`, `application_id`, `rec_id`) ограничены лишь регулярным выражением и
  могут нести скрытый канал (в т.ч. утечку ПДн); «нет свободного текста» верно для содержимого, но не для ID.
* Существование чужих `application_id` различимо по ошибкам FORBIDDEN/UNKNOWN (слабый oracle).
* Хэш-цепочка защищает от случайной порчи, не от злонамеренной переписи (нет подписи/якоря головы); откат хвоста лога
  не обнаруживается.
* Изоляция агентов — по соглашению внутри одного процесса (есть доступ через `__self__`/`_svc`); AST-тесты
  проверяют импорты, а не sandbox.
* Evaluator и oracle доверенные; нет эксперимента с несколькими разнородными авторами и состязательным B.
* Размер выборки: 30 seeds варьируют только поток задач; это не независимые миры. Доверительных интервалов нет.
* Нет эксперимента «локальное обучение по тому же сигналу без B» с собственным корпусом; `2agents_private`
  частично его заменяет (приватный Commons с корпусом B).

## Рекомендации для следующего эксперимента
1. Мир с шумом, задержкой и частичной наблюдаемостью исхода; корпус B, построенный независимо от правил мира.
2. Честный baseline: локальный learner (bandit по контексту) с тем же сигналом исхода, но без B; затем N≥3 агентов
   с разной дистрибуцией задач для измерения реальной передачи.
3. Аутентификация авторов и агентов, владение `rec_id`, перенос репутации между версиями с затуханием.
4. Evaluator, сканирующий мир на исполнения без заявок; подписанный лог с внешним якорем.
5. Состязательный B (отравление корпуса, sybil) и бюджет исследования.
